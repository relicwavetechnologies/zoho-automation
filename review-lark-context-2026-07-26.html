Agreed group-memory design

1 · ListenReceive every visible text message in the Lark group.
2 · RememberAppend it to one bounded context record for that company + group.
3 · RollKeep the newest messages raw; use the fast model only to summarize older overflow.
4 · Stay silentIf Divo is not tagged, save context and stop. Do not run the agent or tools.
5 · Invoke safelyIf Divo is tagged, resolve RBAC only from that current invoker.

Important boundary: room history is information, not authority. A past admin message, a quoted instruction, or another participant can add context, but can never give the current invoker extra permissions.

Hermes learnings to use

Divo should not copy Hermes blindly: Hermes usually isolates a group session per user, while Divo needs one shared ambient memory per Lark room. It should copy the compaction invariants that make Hermes resilient.

Protect the newest conversation

Choose the recent tail by token budget, not only by message count. Always keep the latest user message and latest visible assistant reply raw so the active task cannot disappear into a summary.

Keep causal groups together

Never split a user request from its answer, or a tool call from its tool result. Move the compaction boundary so the complete unit stays on one side.

Update the old summary

On every rollover, send the previous summary plus only the newly aged-out messages to Flash. Produce one refreshed summary instead of repeatedly summarizing the whole room from scratch.

Make recent truth authoritative

Label the compacted block as historical reference. If it conflicts with the newest raw message or current system state, the newest information wins.

Fail without losing history

If Flash times out, returns bad output, or has an auth problem, do not advance the rollover destructively. Keep a deterministic fallback or retryable old chunk, log the failure, and avoid repeated no-op compaction loops.

Serialize one room

Use one update lane or optimistic retry for each company + chat ID. Two simultaneous group messages must not read the same old value and overwrite each other.

Findings

Critical agents/supervisor.ts:193–197, 335–347, 573–576

DM conversation summaries never reach the live governed Lark model

The engine loads a summary and passes it as conversationSummary. The supervisor destructures that value, but its live governed-Lark prompt appends memory and group context only. Once a summary exists, HistoryService returns only messages after the summary checkpoint, so omission of the summary is direct loss of older context.

How to fix

Put the saved summary into the final instructions sent to the AI. Right now it is loaded, but never shown to the AI.

Then add one test that checks the final prompt really contains that summary.

Group rollover now uses a Hermes-style fast compaction path

Production supplies the configured fast model. Every real overflow updates the previous summary while preserving the newest raw tail. Empty model fields cannot erase durable history, late attachment enrichment survives rollover, and compare-and-swap retries prevent blind concurrent overwrites.

Room history is now reference data, not privileged instructions

On the active governed-Lark path, participant transcript is outside the system prompt. The live event is removed from history by message ID, old group turns are not reintroduced, and the final tagged message is the only active request.

What changed

The system prompt receives only a fixed trust rule. Room transcript arrives in a clearly labeled untrusted reference message immediately before the current request.

RBAC still comes from the current invoker. Unused dynamic-path edits were removed; focused checks passed 21/21 and the governed-Lark cold review said ship.

Warning conversation-summarizer.ts:82–131; conversation.repository.ts:292–320

A backlog over 60 turns can be checkpointed past turns that were never summarized

The repository selects the newest 60 rows after the checkpoint. The summarizer then advances to meta.lastMessageSequence - 5. If more than 60 unsummarized rows accumulate, older rows outside that query are skipped permanently.

How to fix

Summarize the oldest waiting messages first.

Move the checkpoint only to the last message that was actually summarized. If messages remain, process the next batch later.

Warning supervisor.ts:317–347, 573–576

The global context budget is not enforced on the governed Lark path

enforceContextBudget is called in the dynamic graph path, while governed Lark bypasses that graph and calls streamText directly with the assembled system prompt and messages. Component-local limits reduce risk, but there is no final model-specific aggregate guard.

How to fix

Check the size of the complete prompt immediately before sending it to the AI.

If it is too large, trim it using the same budget rules used by the other execution path.

Group-summary field formatting, concurrent room writes, unknown speakers, silent busy lanes, and invocation-safe batching now have focused coverage. The unresolved DM summary handoff and backlog checkpoint still do not.

How to fix

Add two small tests with those fixes: a saved DM summary reaches the AI, and every old DM turn is summarized before its checkpoint advances.
