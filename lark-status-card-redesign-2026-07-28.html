Status card: what's lying, and two ways to rebuild it

Read from lark-card.builder.ts, progress-state.ts, run-status.aggregator.ts, narration-buffer.ts · 28 Jul 2026
Built: Option B, with the trace panel removed. The status card is now header (your request) → state + honest counter → optional plan bar → grouped ledger → Stop. Deltas from the mockup below, all found while wiring it up:
  • The live line was cut when it would duplicate the state word or the running ledger row — the ledger's ● row already is the live indicator.
  • No collapsible panel anywhere on the status card (your call: no trace for the user). recent[] — the array that fed “Trace (5)” — was deleted outright, which is what removed the second, contradictory count.
  • Header falls back to the state (“Working…”) when the request can't be summarised.
  • Two bugs the wiring exposed: previewToolResult stripped every hyphen, mangling INV-1043 and dates in the very strings the ledger shows; and manageTodos' checklist dump leaked into a ledger row.
  • The final answer card keeps its execution-trace panel — it's a separate, tested feature. Say the word and it goes too.
Then a cold review found four more, all fixed:
  • Elapsed time is now computed at render from startedAtMs. Baked into the snapshot, it froze — the card's 6s heartbeat re-sends the last snapshot, so a four-minute tool call showed the same “1m 04s” the whole way through.
  • A retry that succeeded after a 429 rendered as “✗ Zoho · 2 calls — Created INV-1043” — failure marker over a success. Marker and outcome now always describe the same call.
  • The checklist dump was stripped in the ledger but not in the final-card trace or the desktop plan subtitle, so internal ids leaked there. Now cleaned once, at the source.
  • The action count is kept beside the fraction (“Step 1 of 5 · 12 actions · 40s”): a model that adds todos and forgets to tick them would otherwise freeze the counter for a whole run.
  • Two things were deleted rather than kept: the terminal “Done/Blocked” status-card branches (unreachable — the final card always replaces the status card) and every standard_icon token on the status card (an unrecognised token makes Lark reject the entire card, costing every run its status bubble).

2 · The one rule that fixes the counter

Aap ne exactly yahi pakda: agent ko pata hi nahi hota kitne steps lagenge — to fraction dikhana hi galat hai. So the card gets three counter modes, and it only ever shows the one it can prove.

mode ATotal unknown → count up

“Working · 6 actions · 38s”. No denominator, ever. Numbers only go up, so nothing can contradict itself. This is the default and covers ~90% of runs.

mode BPlan declared → real fraction

“Step 3 of 5 · ▰▰▰▱▱”. Only when the model has committed a checklist through manageTodos (chat-scoped, already in the DB). The denominator is a promise the model made, not a side effect of counting.

mode CTerminal → totals

“Done · 11 actions · 1m 04s” / “Stopped by you” / “Blocked — Zoho auth”. One line, past tense, no ellipsis, no spinner.

And: one number per card. If the header counts actions, the panel title must not count something else — it becomes “All 11 steps”, driven by the same array. The 5-line recent[] cap moves inside the panel where it belongs (“showing last 5”).

3 · Two structures

Both are driven by the same run state below, so you're comparing them in identical situations — scrub the stages or hit Play. Both drop the ring, the fraction, the constant headline and the duplicate count. Every element used is one Card 2.0 supports (markdown · hr · collapsible_panel · column_set · button).

Option A — Status line

The header is the status. Body = one bold live line, one grey “what just landed” line, everything else folded away. Smallest honest card possible.
  • Measured height (this preview, same metrics as Lark PC): 142px starting, 206px mid-run, 222px answer — against 263px for today's card.
  • Body is 4 elements max: live line · one grey outcome · collapsed panel · Stop.
  • Moves: the live line + the seconds. Nothing else redraws, so no jitter at the 1.5s update rate.
  • Header: title carries state (“Thinking…” → “Working…” → the answer's subject), subtitle carries the honest counter. Lark already prints “Divo · BOT” above, so the old “Divo AI” title was a duplicate.
  • Best if you want the card to feel like a system line, not a dashboard.
  • Trade-off: only the newest outcome is visible; the rest is one tap away in the panel.
