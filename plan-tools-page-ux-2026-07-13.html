The UX pitch

A scope-first control surface for department managers

Recommendation

Replace the team summary block with a persistent department scope.

People, roles, and tool access are not separate jobs. They are different views of the same department policy, so they should share one context and one search model.

01

Select scope before action

The manager always sees which department they are changing and that company policy remains the ceiling.

02

Make the common path obvious

Browse tools, open one, change role defaults. People and custom roles remain one click away without dominating the catalogue.

03

Search means the manager's question

The same field finds tools, actions, people, and roles. Results adapt to the current view; “create” can lead directly to the access map.

04

Show effective access first

Configured access, member exceptions, company ceilings, readiness, and approval requirements are explained where they affect a decision.

05

Use a matrix for cross-tool questions

Managers can audit a role across all tools without opening and mentally combining eight separate detail pages.

Risks to validate

  • Information density: test the access map with departments having 20+ roles and 50+ tools; add virtualization if needed.
  • Immediate writes: high-impact actions may need confirmation or an undo window even though current writes are immediate.
  • Search contract: backend search currently covers tool metadata only; unified people/role search needs a deliberate API or local snapshot strategy.
  • Policy language: “configured” versus “effective” must be usability-tested with real managers.
