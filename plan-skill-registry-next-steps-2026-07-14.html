Next: make the backend registry scalable and administrable.

Cloud-only Divo Dex routing is complete in source. The immediate next work is backend-owned retrieval quality and the data model needed for a real admin registry—not the file-browser polish yet.

Recommendation

Build backend search and audit first, then folders/versions, then the admin UI. This protects the authorization boundary while giving the team a usable registry foundation.

1. Cloud-only boundary — complete in source

Rebuild Divo Dex through the normal vendor/build path to regenerate its bundled resources before manual desktop testing.

Next implementation ticket: backend retrieval

Change

  • Make Pi call skills.search first; do not retrieve a capped catalog then rank it locally.
  • Return skillId, version, and registryRevision.
  • Audit search, get, denial, and invocation.

Tests

  • RBAC-filtered search results.
  • Revoked skill cannot be fetched.
  • Version/cache refresh after publish or archive.
  • Backend unavailable has no local fallback.

Exit criteria

  • Only top ranked eligible skills reach Pi.
  • Admin changes appear quickly.
  • Every selected skill is traceable to a user, department, session, and version.

After that

Registry schema

Add SkillFolder, immutable SkillVersion, capability/action bindings, aliases, and audit events. Keep existing Skill records; migrate without deleting.

Admin UI

Build three panes: folder tree, skill list, and editor/preview. Use existing admin UI dependencies first; defer tree/drag packages until the data model is stable.

Scale gate

Add PostgreSQL full-text search with a GIN index, then benchmark 10k and 100k synthetic skills before changing VPS infrastructure.

Risks to keep visible

Bundled artifact freshness

The source change needs the standard Divo Dex vendor/build run to refresh packaged resources.

Instructions are not permissions

Continue enforcing tool RBAC and approvals in the backend, regardless of skill text.

Unknown VPS capacity

Do not claim a scale limit before measuring the production-shaped search query.
