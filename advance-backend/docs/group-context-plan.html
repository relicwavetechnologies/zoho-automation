Group Chat Context — What's Broken & How to Fix It

Why Divo picked up "Review pending invoices" instead of "duplication of text pr work krna h"

The Problem (Screenshot)

Abhishek Verma

Abhishek Verma
@Divo make todos of the above message
Divo AI
I have added a todo for you to review the pending invoices list sent to your email.
What went wrong
Divo ignored the message right above ("duplication of text pr work krna h") and instead acted on something from much earlier in the conversation. The "above message" reference resolved to stale context.

Current Architecture (What Divo Sees)

What gets injected into the LLM prompt
SYSTEM PROMPT: You are Divo's supervisor agent... MEMORY CONTEXT: facts from mem0... GROUP CHAT CONTEXT: [Rolling summary of older group discussion] Summary: Team discussed invoice processing... Decisions: Use Zoho for billing... Open questions: ... [Recent raw group transcript - latest 47 messages] [2026-05-13T10:00:00Z] f6312e2b-d0d3: some old message [2026-05-13T10:01:00Z] f6312e2b-d0d3: another old message ... 45 more messages ... CONVERSATION HISTORY (separate, from DB): user: previous @Divo message assistant: Divo's previous reply user: another @Divo message assistant: another reply CURRENT USER MESSAGE: make todos of the above message
3 Problems
1. "Above message" is ambiguous
The LLM sees THREE contexts: group transcript, conversation history, and current message. When user says "above message", which "above"? The LLM picks from whichever context it attended to — often the conversation history (old @Divo exchanges), not the raw group transcript.
2. Sender names are UUIDs
The transcript shows f6312e2b-d0d3 instead of Abhishek Verma. The LLM can't tell who said what. The storeGroupChatMessage function resolves userId but stores the internal UUID, not the display name.
3. No clear boundary between "room chat" and "Divo conversation"
The group context and conversation history are two separate blobs appended to the prompt. There's no clear signal telling the LLM: "THIS is the latest group message right before the @Divo mention."

Proposed Fix — Clear, Simple, Unambiguous

What the LLM should see instead
SYSTEM PROMPT: You are Divo's supervisor agent... MEMORY CONTEXT: facts from mem0... GROUP CHAT CONTEXT This is a group chat. Below is the recent conversation in this group. When the user refers to "above", "previous message", or "that", they mean the messages in this transcript — read from top (oldest) to bottom (newest). ── ROLLING SUMMARY (older discussion, ~15k tokens) ── The team has been discussing Q4 invoice reconciliation, vendor payment schedules, and Zoho Books data accuracy improvements... ── RECENT MESSAGES (raw transcript, ~15k tokens) ── [12:00 PM] Abhishek Verma: checked the zoho bills looks good now [12:01 PM] Anish: great, what about the CRM sync? [12:02 PM] Abhishek Verma: will check tomorrow [12:05 PM] Abhishek Verma: duplication of text pr work krna h, history refreshing par wokr krna h ▶ [12:06 PM] Abhishek Verma → @Divo: make todos of the above message ── CURRENT REQUEST ── The user's latest message is the LAST line above (marked with ▶). "The above message" refers to the message directly before it in the transcript.

Key Differences

Implementation Steps

1
Fix sender name resolution
In storeGroupChatMessage() — resolve Lark open_id to display name (not userId UUID). Use the existing LarkPeopleResolver or channel identity repo's display name field.
2
Merge the current @Divo message into the transcript
In engine/core.ts — append the current user message as the LAST line of the group context transcript (marked with ▶), instead of passing it separately. The LLM sees one continuous conversation, not two disconnected blobs.
3
Merge Divo's past replies into the transcript
Old @Divo turns from conversation history should appear IN the transcript at their chronological position, not as a separate "conversation history" section. This way "above" always means "the line before this one in the transcript."
4
Simplify the summary format
Replace the structured JSON summary (decisions, blockers, owners arrays) with a simple prose paragraph: "The group has been discussing X, Y, Z. Key decisions: A, B." The LLM reads prose better than labeled arrays.
5
Add clear prompt framing
The group context section should start with: "When the user refers to 'above', 'previous message', or 'that', they mean the messages in this transcript." This eliminates the ambiguity.
6
Increase raw transcript budget
Bump from 15k to 20k tokens. In a busy group, 15k is ~50-80 messages — barely a few hours. 20k gives better coverage.
