What this is

Lark interactive cards (JSON 2.0) are not “text only.” They are a component system with layout, charts, tables, and buttons — but no custom CSS. This catalog maps every Divo message-bubble state to real Lark components: what we ship today, what’s available, and what’s worth adding in a polished revamp (without over-building).

Requires Lark client ≥ 7.20. Cards update in-place via update_multi: true during runs.

Platform constraints (read first)

These are hard limits — design inside them and the product feels native; fight them and cards break silently.

No custom CSSOnly Lark tokens: colors, spacing presets, component styles.
200 elements maxPer card. Prefer collapsible sections for long plans/traces.
5 tables / 5 chartsMax per card. Status card uses 1 chart — leave headroom on final.
Table placementNative table must be top-level in body.elements (not inside columns).
In-place updatesSame message ID morphs: status → final. Must drain pending flushes (fixed).
Rate limits~1.5s between status PATCHes. Don’t animate every token — update on tool boundaries.
Collapsiblecollapsible_panel is JSON-only (no builder UI) but works in production.
Headertitle, subtitle, text_tag dept chip, template colors (v1 approval uses orange/green).

Revamp tiers (polished, not overloaded)

Recommended scope for the full revamp. Tier 1 = must match this catalog; Tier 2 = next sprint; Tier 3 = deliberately skip.

Tier 1 — Ship now

  • Status: header subtitle + progress chart + live column
  • Plan + Recent: collapsible, collapsed by default
  • Final: prose + native table when markdown has pipes
  • Trace: collapsible, collapsed
  • finalizeMessage (no overwrite race)
  • Synthesizing phase at 100% tools

Tier 2 — Polish

  • HITL: primary/danger buttons on status card
  • Failed: Reconnect Zoho / Google button
  • div + standard_icon for step rows (less emoji)
  • Header template tint (blue=run, green=done, red=fail)
  • person_list on “created task for @user”

Tier 3 — Skip

  • Forms, selects, date pickers in chat
  • Pie/line charts, word clouds
  • Multiple charts per status card
  • Custom CSS / HTML injection
  • Second message for final (breaks single-bubble UX)

Lifecycle (one bubble)

Same message_id from first status PATCH until final PATCH replaces the card body.

User message
    → [1 Routing]     sendMessage (new card)
    → [2 Planning]    updateMessage
    → [3–5 Executing] updateMessage (rate-limited, plan/recent collapsed)
    → [6 HITL?]       updateMessage + action buttons
    → [7 Synthesizing] updateMessage (~92%)
    → [8–10 Final]    finalizeMessage (drain flushes → replace with answer/table/trace)
