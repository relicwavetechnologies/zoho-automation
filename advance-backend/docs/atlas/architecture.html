Architecture

One brain, two channels

The desktop app is a thin channel over the same orchestration engine that powers Lark. Nothing about planning, tools, permissions or memory is desktop-specific — the desktop adapter just translates the engine's events into a WebSocket stream the Tauri client renders.

Request → response, end to end

A desktop message walks the exact same path a Lark message does, after the channel adapter normalises it.

Layered dependency direction

Enforced, never broken: http → application → domain ← infrastructure.

LayerResponsibilityDesktop touch-points
http/ Express routes + the desktop WS gateway. Auth, payload parsing, per-thread serialisation. desktop-ws.gateway.ts
application/ Orchestration engine, supervisor graph, tool framework, approval gates, memory. Channel-agnostic. engine/core.ts · StatusChannel
domain/ Pure types — channel outbound events, conversation, permissions. Imported by all layers. channel/outbound.ts
infrastructure/ External integrations behind adapters. The desktop channel adapter lives here. channels/desktop/desktop.adapter.ts

The streaming bridge

How the engine's internal events become pixels. The supervisor never knows it's talking to a desktop — it calls StatusChannel methods, and the desktop adapter forwards them as WS frames.
