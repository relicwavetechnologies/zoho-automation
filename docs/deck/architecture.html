Unified brain. The model never calls tools directly — it calls one meta-tool, call_tool, which looks up the registry, enforces permissions, runs the approval gate, and dispatches by toolId. This is the migration principle: adding Ahrefs, WordPress, or terminal tooling is a registry update, not a graph rewrite.
Add a new domain — in three steps

Growth pattern. The architecture is built for velocity: add integration shape, teach intent in one skill, then register it. No core loop changes. No rewrite. This is what makes channel parity in one week realistic.

1

Make a tool

A typed interface over the API — list · create · update. Zod-validated in, structured out.

2

Make a skill

A short prompt that tells Divo what it's for, its verbs, and its guardrails — so it knows when to use it.

→
3

Register it

One line in the registry + RBAC defaults. call_tool discovers it automatically.

Worked example · Airtable new domain

From nothing to “Divo, sync this month's placements into the Airtable outreach base.” One tool (airtable.records.*) + one skill (“Airtable Operations”), registered — and Divo now reads, writes and syncs bases on command, RBAC-scoped. Hours, not a rebuild.

register the capabilitycomposition.ts
const airtable = makeAirtableTool(env)   // 1 · the tool
registry.add('airtable', airtable)
skills.load('airtable-ops')            // 2 · when to use it
// 3 · done — call_tool can now run Airtable jobs
That's the loop. A new domain — Airtable, WordPress, a payments rail — moves from idea to execution in days, because all tools connect through the same call_tool contract and RBAC policy chain.

Governance and reliability layer

Clean layering · enforced

dependency direction
http  →  application  →  domain  ←  infrastructure
  • domain/ is imported by all; depends on none.
  • Channel payloads never leak past channels/.
  • Integrations sit behind adapter interfaces.
  • Every LLM call goes through the Vercel AI SDK.

Memory, context & proactivity

  • 3-layer context management — tool-result masking, background summarization, a global token budget.
  • Mem0 + Qdrant — user / department / company facts, recalled into context.
  • RAG ingestion — PDF, Office, CSV, images (OCR) → vector store with per-file access control.
  • Scheduled workflows — timezone-aware briefings that run the same engine on a timer.
  • HITL approval gates — pause / resume on LangGraph checkpoints.
Ops confidence layer. Context, approvals, and auditability are part of the same run path — this is what lets Divo serve one company with different roles safely.
