Architecture

Keep the authority boundary

Identity, department context, tool credentials, RBAC, approvals, memory, and skill grants remain backend-owned. This is the correct center of gravity.

Reliability

Ingress and final delivery now share recovery

A failed final delivery rejects durable ingress, preserving the receipt for retry. The stored payload is resent on the next attempt without rerunning the agent or its tools.

UX

Happy paths are polished; failure states collapse

Sign-in cards, status cards, synthesis recovery, and file excerpts are strong. Missing scopes, unsupported media, stale grants, and legacy commands remain inconsistent.

Findings

Filter by severity. Every item points to the current source location and proposes a bounded fix.

Resolved

Completed answers remain retryable after final-delivery failure

lark.webhook.routes.ts:610–630, 730–759, 1266–1278, 1338–1351 · lark.webhook.routes.test.ts:1875–1935

Both engine call sites now inspect the persisted delivery state after an error. When a resendable payload remains, processing rejects so the ingress worker keeps the receipt retryable; the next attempt sends the stored answer before considering a new agent run.

Implemented and verified

The regression proves: tools run once → first delivery fails → the stored payload is resent → tools do not rerun. Default-on rapid-message batching is covered too, so absorbed receipts close with the stored answer instead of later executing separately. Validation: 70 webhook-route tests, 36 worker/repository/adapter tests, and TypeScript typecheck passed.

Resolved

Department changes no longer falsely sign out valid multi-department users

lark.webhook.routes.ts:861–910 · lark.webhook.routes.test.ts:963–1014

The selected department is now validated with an exact company-scoped findFirst. Only when that lookup proves the selection stale does the route fetch up to two remaining memberships, choose an unambiguous replacement, revoke the old connection, and offer reconnect.

Implemented and verified

A three-membership regression places the selected Finance department after Tech and Operations and proves the agent continues without revocation. The existing genuine-removal test still proves that stale Finance access signs out, switches to the sole Tech membership, invalidates identity cache, and renders the Connect card.

High

A manager can publish a skill into another department’s namespace

skill-publishing.tool.ts:249–281 · gateway/tool-executor.ts:720–769

The tool accepts a supplied department ID but tests authority using the current permission object. It never requires the requested department to equal the active run-context department before writing the skill and grant.

Exact fix

Apply the same invariant already used by memoryPublishing: the requested department must equal both run context and permission department, or permissions must be freshly resolved for that exact target.

High

Company skill publishing reports success but creates no discoverable grant

skill-publishing.tool.ts:148–218 · skill-access.repository.ts:8–38

A company skill is stored as global with no department. The transaction creates an access grant only when a department exists, while runtime discovery requires an explicit company, department, role, or user grant.

Exact fix

Create a company grant in the same transaction for company scope. Test the full path from publish result to listGrantedSkillIds and Lark discovery.

High

/remember bypasses reviewed, secret-safe memory publishing

lark.webhook.routes.ts:1517–1550 · share-memory-system-skill.ts:13–18

The legacy command chooses company, department, or personal scope from role and writes directly to Mem0. It skips the review card, credential-like fact rejection, current target selection, live authority recheck, and “no silent downgrade” contract.

Exact fix

Route /remember through the same requester-owned review service as conversational Share Memory, or retire the command. Do not maintain a second memory-write authority.

High

Inbound files are buffered without a byte ceiling

clients/lark-file.client.ts:29–43 · lark.webhook.routes.ts:1893–1925

The file client accumulates every stream chunk and concatenates the full payload before the 4 MB inline-image check. Several concurrent large Office/PDF files can create memory and parser pressure.

Exact fix

Stop the stream at a configured byte limit before buffering or parsing, return an actionable “file too large” context, and reuse the bounded streaming pattern already present for quoted parent images.

High

Approval authority can become stale before the click

approval-gate.service.ts:140–175 · lark-approval-card.handler.ts:150–221

The approval stores the chosen manager for up to 24 hours. The click handler proves actor identity, company, tenant, and stored IDs, but does not re-check that the person is still a manager/admin/connection owner.

Exact fix

Resolve the required authority again immediately before atomicResolve. Cover revoked role, removed department membership, and lost connection ownership.

High

Approved work can be stranded in a crash window

lark-approval-card.handler.ts:216–250 · approval-inbox.service.ts:127

After the decision is atomically recorded, resume is launched fire-and-forget. A crash after resolution but before or during resume leaves approved/executing work without a durable owner or startup scanner.

Exact fix

Write a durable execution job/outbox keyed by approval ID in the decision transaction, consume it idempotently, and recover stale executions.

Medium

Missing auth states collapse into a generic connect loop

composition.ts:1405–1452 · lark-user-connection.ts:74–75 · lark.webhook.routes.ts:1655–1661

No connection, insufficient shared access, missing token, failed refresh, repository outage, and missing OAuth scope all become “connect a Lark account.” Stored scopes are not preflighted per tool operation, so some failures arrive late as provider errors.

Exact fix

Return typed readiness states—not_connected, missing_scope, refresh_expired, insufficient_access, registry_unavailable—and render the correct retry, reauth, account-choice, or admin path.

Medium

One monolithic OAuth grant makes basic sign-in brittle

lark-oauth.service.ts:54–89, 129–137

Identity linking requests a large all-capabilities scope set. One invalid or unpublished capability scope can block the entire sign-in flow, including basic identity and offline access.

Exact fix

Separate base identity/offline access from incremental capability grants, or add boot-time compatibility checks that disable only the affected tool family and produce an admin-actionable diagnostic.

Medium

Post-login “no need to resend” replay is best-effort

lark-auth.routes.ts:345–351 · lark.webhook.routes.ts:442–489 · lark-signin.ts:44–52

The UX promises to answer the pre-login question, but callback replay is fire-and-forget and explicitly has no durable retry if its lane is busy or the process exits.

Exact fix

Persist a replay job/outbox using the original event identity and enqueue it after the OAuth transaction. Reuse the normal lane and delivery idempotency path.

Medium

Unknown slash commands disappear silently

lark.webhook.routes.ts:1227–1242, 1787–1789

The command handler logs that an unknown command is routed to the engine, but its caller always returns immediately afterward. The engine never receives the message and the user gets no reply.

Exact fix

Return a handled boolean from the command handler. Continue to normal orchestration when false, or reply with command help.

Medium

Audio, video, and other media can be silently ignored

lark-attachment.parser.ts:1–8, 70–104 · lark.webhook.routes.ts:1265–1267

The parser understands files, images, and images inside rich posts. Other message types can produce neither text nor attachments, after which the webhook returns without a user-facing refusal.

Exact fix

Declare the product policy per media type: support/transcribe it, or respond immediately with supported formats. Add DM and mentioned-group cases.

Medium

A failed document download is described as an image failure

lark.webhook.routes.ts:1954–1961 · lark-media-support.ts:176–186

The generic fallback always calls unreadableImageNotice. A failed PDF or spreadsheet download therefore gives the model an “Image” notice and asks the user to resend an image.

Exact fix

Use a type-aware unreadable attachment notice and assert the engine prompt for a failed document download.

Medium

Indexing admission failure leaves the transcript at “processing”

lark.webhook.routes.ts:1950–1982, 2004–2075

The transcript status is set before enqueue. Missing queue wiring or an enqueue exception returns false, but the caller ignores it; no worker exists to later replace “processing.”

Exact fix

On enqueue failure, update the stored attachment to inline_only or failed and preserve the inline excerpt.

Medium

Long replies are not idempotent per continuation segment

domain/channel/delivery-key.ts:13–16 · lark.adapter.ts:316–327, 752–768

The domain models a segment index, but the adapter reserves the entire answer once and sends continuation cards without deterministic provider keys. A partial-send recovery can duplicate previously delivered continuations.

Exact fix

Reserve, send, and mark every planned segment independently with a deterministic segment idempotency key.

Medium

/clear promises more forgetting than it performs

lark.webhook.routes.ts:1487–1513 · engine/core.ts:331–340, 713+

The command clears chat history and group context, then says Divo will “start fresh.” Persistent personal, department, and company memories remain searchable, and Lark has no inspect/forget/disable lifecycle.

Exact fix

Rename the outcome to “chat history cleared” and add explicit memory list, forget, and disable controls with confirmation before describing the experience as fresh.

Medium

Instruction-only skills are valid but hidden from Lark

skill-catalog.service.ts:149–165 · supervisor.ts:296–318

The catalog deliberately accepts a granted skill with zero tools, but Lark filters visible skills using toolIds.some(...), which excludes every instruction-only recipe.

Exact fix

Include granted zero-tool skills. Keep the executable-tool intersection only for recipes that declare tools.

Dead-letter recovery remains operator-only

lark-ingress.worker.ts:110–133

Receipts are correctly retained and dead-lettered after the six-hour retry window, but there is no operator replay surface or user notification. Recovery is manual.

Exact fix

lark.webhook.routes.ts:1–2195

One module owns HTTP admission, identity bootstrap, auth commands, media preparation, transcript snapshots, indexing, routing, and orchestration. Its tests are strong, but unrelated Lark work repeatedly collides here.

Exact fix
