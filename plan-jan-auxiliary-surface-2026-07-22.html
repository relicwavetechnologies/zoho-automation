Jan Auxiliary Surface

Right-rail architecture for Artifacts, Side chats, and future surfaces — designed as a typed tab host from day one, not an artifact-only drawer bolted onto chat.

TL;DR

Build a generic Auxiliary Surface (VS Code’s secondary side bar pattern): a docked, resizable right rail whose only job is to host typed tabs. Artifact and Side chat are the first two tab kinds — not special-cased panels.

  • Do not create useArtifactPanel that later gets forced to also host chats.
  • Do separate Shell (layout/resize) · Tab Host (open tabs) · Surface Renderers (content).
  • Jan already has react-resizable-panels and a right-aware use-sidebar-resize — reuse those; don’t invent a third resize system.

Context

What’s decided vs still open for this plan.

Decided

Product intent

  • AI research / detailed reports render as Artifacts in a right sidebar
  • Users can open chats as tabs in the same rail
  • More kinds will come later (browser, files, terminal, review…)
  • Agent eventually calls a tool like artifact — but this plan is UI/host first
  • No implementation in this pass — architecture only
Open

Still to choose later

  • Whether tabs are URL-backed or ephemeral UI state (recommend ephemeral v1)
  • Thread-scoped vs app-global tab lifetime
  • Auto-open on agent artifact tool vs click-to-open (LibreChat moved to manual for code)
  • Whether side chats share useChatSessions or a sibling store

What the ecosystem taught us

Patterns that hold up, and the failure modes that make sidebars feel “never quite right.”

Gold standard

VS Code Auxiliary Bar

Secondary side bar is a part of the workbench, not a feature of any one view. Views (chat, timeline, etc.) register into it. Layout owns visibility/size; content is pluggable.

Closest product

Cursor / Codex right pane

Empty state = launcher (Review, Terminal, Browser, Files, Side chat). Active state = multi-surface host. Side chats are durable parallel threads, not popovers. Your screenshot is this model.

Open source

HF chat-ui · Artifactuse · Morphic

Sibling flex/resizable panel next to chat; sandboxed preview; multi-tab opt-in; mobile → fullscreen overlay. Morphic: open artifact closes left sidebar to reclaim width.

Anti-patterns

What breaks sidebars

  • Floating artifact cards — Codex VS Code issue: detached from layout, fights scrollbar/composer
  • Artifact-first store — later bolted to host chats; kinds fight each other
  • Register/unregister on mount — Archestra fixed by deriving canvases from messages instead
  • Auto-open everything while streaming — LibreChat retreated to manual-open for code artifacts
  • Hard-coded chat column % — ignores rail open state (Jan today: md:w-[58%])
  • Dual sources of truth — Jan left panel already has Zustand + cookie in SidebarProvider
Winning patterns

What to copy

  • PanelGroup sibling layout — ChatJS / react-resizable-panels: main + handle + secondary
  • min-h-0 + independent scroll — each column scrolls alone
  • Iframe resize overlay — portal a full-screen shield while dragging so iframes don’t steal mouse
  • Discriminated tab kinds — Artifactuse multiTab: openTabs[] + per-tab view mode
  • Empty launcher state — Codex: tools list until a tab opens
  • Keep content after close briefly — Morphic clears after exit animation

Critical: the agent never “owns” the sidebar. It only emits/opens a tab descriptor. The host decides layout. This matches Divo’s backend-authority rule — UI shell stays desktop-owned.

Tab model (the durable core)

Discriminated union from day one. Adding Browser later = new kind + renderer, zero shell changes. 

{span class="kw">type AuxiliaryTabKind = 'artifact' | 'sideChat' // | 'browser' | 'files' | 'terminal' | 'review'

type AuxiliaryTabBase = {
  id: string
  title: string
  createdAt: number
  originThreadId?: string  // which main chat opened this
}

type ArtifactTab = AuxiliaryTabBase & {
  kind: 'artifact'
  artifactId: string
  mime?: string           // text/html, text/markdown, …
  version?: number
}

type SideChatTab = AuxiliaryTabBase & {
  kind: 'sideChat'
  threadId: string         // secondary conversation id
  parentThreadId?: string
}

type AuxiliaryTab = ArtifactTab | SideChatTab

type AuxiliaryTabsState = {
  tabs: AuxiliaryTab[]
  activeTabId: string | null
  openTab: (tab: Omit<AuxiliaryTab, 'id' | 'createdAt'> & { id?: string }) => string
  focusTab: (id: string) => void
  closeTab: (id: string) => void
  reorderTabs: (ids: string[]) => void
}

type AuxiliaryShellState = {
  open: boolean
  width: string              // e.g. "28rem"
  setOpen: (v: boolean) => void
  setWidth: (w: string) => void
}

Focus rules

  • Opening a tab → shell opens + that tab focused
  • Re-opening same artifactId / sideChat threadId → focus existing (no duplicate)
  • Closing active → adjacent tab; if none → empty launcher (rail can stay open)
  • Closing rail ≠ destroying tabs (optional: keep tabs in memory while shell closed)

Lifetime (v1 recommendation)

  • Ephemeral UI state — no URL for tabs yet
  • Thread-scoped cleanup — leaving a main thread can close orphaned artifact tabs from that origin (configurable)
  • Side chats: durable enough to revisit in-session; persistence = later
  • Don’t sync rail open state into Pi / backend

Phased delivery (UI-first)

Matches your “no logic change yet” constraint while still rooting the architecture correctly.

  1. Phase 0 — Shell + empty host Mount AuxiliaryRail, resize, persist width/open, empty launcher UI (Side chat / Artifacts stubs). No agent tools. Prove reflow of chat column.
  2. Phase 1 — Artifact tabs (UI only) Promote / “Open in sidebar” from existing HtmlArtifact or a mock report. Multi-tab, focus, close, preview/code modes. Still no agent tool.
  3. Phase 2 — Side chat tabs Secondary conversation UI in a tab; inherit parent thread context at spawn (Cursor /side pattern). Decide session store sharing.
  4. Phase 3 — Agent artifact tool Backend/gateway op emits artifact payload → desktop opens tab via same openTab. Enforcement stays backend; Pi just calls the tool.
  5. Phase 4 — More kinds Browser / Files / Terminal / Review as new kinds + launchers — shell untouched.

Risks & open questions

Chat column geometry fights the rail

Mitigation: kill percentage-of-viewport composer widths; Main panel content uses max-w relative to its panel, with min-w-0.

Iframes swallow resize drags

Mitigation: portal a transparent overlay during drag (Archestra / Morphic pattern). Especially important once Artifact HTML previews land.

Tab explosion / memory

Mitigation: cap open tabs (e.g. 8), LRU close, or thread-scoped cleanup. Don’t keep infinite side chats alive.

Temptation to special-case Artifact

Mitigation: code review rule — no if (isArtifact) … in Shell. Kind switches only inside Surface router.

Left + right both open on laptop widths

Mitigation: Morphic-style optional auto-collapse of left nav when auxiliary opens under a breakpoint; or min main column 400px hard clamp.

Next steps

  1. Lock the names Call it Auxiliary Surface / AuxiliaryRail — not ArtifactPanel. Document the three-layer rule in a short ADR.
  2. Spike Phase 0 only Empty rail + resize + chat reflow on one thread route. Validate feel before tabs.
  3. Add shadcn Resizable wrapper Wire the already-installed react-resizable-panels; avoid a custom drag system unless PanelGroup can’t meet min-width clamps.
  4. Define tab kind registry Map kind → icon, launcher label, shortcut, Surface component. Extensibility lives here.
  5. Defer agent tool Until host is stable. Tool contract should be “emit tab descriptor,” not “render sidebar.”
