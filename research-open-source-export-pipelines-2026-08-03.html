Research brief · 03 Aug 2026

Make export a durable product, not a lucky background job.

A primary-source scan of open-source workflow engines, data-sync systems, AI Workspace agents, and Drive/Sheets connector patterns. The useful common thread is simple: bounded source reads, durable progress, idempotent side effects, and a verification receipt before delivery.

The short answer

Borrow the state machine, not the UI.

Recommendation: model every export as a resumable state machine with a durable source checkpoint and a separate artifact lifecycle. Do not let a retry re-run a completed source page or re-create a Google Sheet without first checking the deterministic resource identity.
01 / best execution pattern

Step-level replay

Activepieces checkpoints completed steps and replays only the first in-flight step after a crash. That keeps retries from re-sending every earlier side effect.

02 / best source pattern

Committed page cursors

Airbyte checkpoints only after the destination confirms persistence, then resumes from that state. It explicitly accepts at-least-once delivery so reliability does not depend on fragile exactly-once behavior.

03 / best artifact pattern

Pointer + receipt

NiFi keeps FlowFile content behind a pointer and records attributes, routing, and provenance separately. Divo should return an opaque artifact reference plus verification metadata, not the rows themselves.

04 / best agent boundary

Strict JSON + MIME rules

Google Workspace CLI exposes structured JSON and bounded pagination; Anthropic’s Drive skill reads metadata first, branches by MIME type, and rejects unsupported or oversized reads clearly.

Reference set

What each project teaches.

Licensing is called out because “open source” is not uniform. Reuse the design pattern; inspect the license before embedding code or a runtime.

Workflow engine · MIT community edition

Activepieces

Google Drive and Sheets pieces expose read, list, upload, export, row, and write-back actions. Its durable execution model stores a compressed run log with each finished step’s input, output, status, and error; a fresh worker skips completed steps and re-runs only the first unfinished one.

Use for: crash-safe replay Durable execution ↗
Orchestrator · Apache 2 core

Kestra

Its Google Drive plugin covers upload, download, export, list, and file-created triggers. Kestra distinguishes task retries from flow restart/replay, and stores large data in internal storage while task outputs carry references and metadata rather than the payload.

Use for: lifecycle semantics Drive plugin ↗
Developer platform · AGPL core / commercial packaging caveat

Windmill

Google Drive and Sheets credentials are modeled as workspace resources. Drive push channels are renewed automatically; jobs have UUIDs, logs, results, metadata, and progress APIs. Its docs recommend object storage for large binary data instead of step-local state.

Use for: resource + job model Triggers ↗
Data sync · open-source platform

Airbyte

Airbyte’s checkpoint protocol emits state as pages progress and only treats a checkpoint as committed after the destination confirms it persisted the records. Resumable full refresh uses the last successful page as a synthetic cursor, while accepting possible duplicates as an at-least-once tradeoff.

Use for: page recovery Resumable refresh ↗
Orchestrator · Apache 2

Apache Airflow

Google providers make the source/sink boundary explicit: SQL-to-Sheets, local-filesystem-to-Drive, and Sheets-to-GCS transfer operators. Connections, templated IDs/ranges, impersonation, retries, and returned resource URIs stay in the orchestration layer.

Use for: typed transfer steps SQL → Sheets ↗
Dataflow · Apache 2

Apache NiFi

NiFi’s Google Drive listing processor can track entities across a cluster without duplicating a full listing after primary-node failover. Its FlowFile model, backpressure, retry/penalize/yield rules, failure relationships, and provenance replay are unusually useful references for export evidence.

Use for: lineage + backpressure ListGoogleDrive ↗
Task engine · persistence + caching

Prefect

Prefect treats persisted results as the foundation for retries, caching, and later retrieval. Its docs explicitly warn that local result storage does not survive a new ephemeral container; remote object storage or a shared volume is required across retries.

Use for: deterministic cache keys Result persistence ↗
Agent boundary · Apache 2

Google Workspace CLI

The CLI generates its command surface from Google Discovery, returns structured JSON, supports bounded auto-pagination as NDJSON with page limits and delays, and offers explicit upload/auth paths for headless operation. It also ships agent skills.

Drive read/export skill · open repository

Anthropic Google Drive skill

The skill reads metadata first, branches on MIME type, exports Google-native files to explicit formats, limits large stdout reads, writes larger outputs to a file, and exposes clear exit codes and provider error reasons.

AI knowledge app · open source

Onyx

Onyx separates connector credentials, connector configuration, access type, input mode, refresh frequency, and prune frequency. Its Google Drive connector supports Docs, Sheets, Slides, common office files, and permission synchronization when the source account can provide directory access.

AI research app · MIT / prototype caution

Google Workspace Agent

This MIT project combines a typed DAG, persisted state, a five-step verification engine, read-only-by-default behavior, manual confirmation for writes, and sandboxed code execution. Treat it as a useful agent UX/checklist reference, not as proof of production scale.

SurfSense

SurfSense connects Google Drive and other sources, offers report export to PDF/DOCX/HTML and other formats, and describes scheduled/event-triggered agents that write results back to tools including Drive. It is a useful product-shape reference for “research in → deliverable out.”

Divo translation

Robustness backlog, in priority order.

These are recommendations inferred from the references and the handover’s current Google Sheet/CSV/XLSX E2E shape.

  1. Make the offer immutable. Freeze the source operation, arguments, requested limit, ordering, selected columns, and format at confirmation. A callback must replay the frozen offer, never reconstruct intent from chat.
  2. Persist page checkpoints only after durable staging. Commit pageToken/pageIndex/rowsRead after the page has been written to staging. This follows Airbyte’s “destination echoes committed state” model and prevents a cursor from claiming rows that were never persisted.
  3. Separate transient retries from side-effect retries. Retry source reads and artifact verification with bounded backoff. For Google Sheet create/write/upload, first look up the deterministic artifact key and resume/update rather than blindly creating another file.
  4. Use a staging artifact or staging sheet. Build into a temporary object or hidden worksheet; publish/rename only after row count, column order, values, and type checks pass. A visible half-export should never be the “completed” artifact.
  5. Make the sink idempotent per format. Key the artifact by offerId + sourceFingerprint + format + destination. Same format after completion returns the existing resource; a different format gets its own resource, matching the handover’s intended behavior.
  6. Keep the model on a receipt. Return artifactId, provider URL/download reference, status, rows exported, columns, source-truncated flag, and verification status. Keep rows in backend/object storage, never in Pi context.
  7. Record provenance as first-class data. Log source pages, API request metadata without secrets, checkpoint transitions, worker/job IDs, provider resource IDs, artifact checksums or byte sizes, and verification results. This is the Divo version of NiFi provenance and Windmill job metadata.
  8. Verify provider state after every publish. For Sheets, re-read the written range. For CSV/XLSX, parse the artifact back and compare rows/columns/types. A successful API response is not proof that the artifact is correct.
  9. Make continuation use the same opaque resource. Store the provider resource identity and worksheet/tab in the artifact registry. “Edit the exported Sheet” must resolve that resource, not create a new export path.
  10. Test crash windows intentionally. Inject failure after page read, after staging, after Sheet create, after batch write, before verification, and after verification. Assert no extra rows, no duplicate artifact, correct resume point, and correct idempotent callback behavior.
Failure semantics

The edges that deserve tests.

A robust export is mostly about what happens when the provider, worker, or user acts twice.

Source edge

Limit changes mid-run

Freeze the original limit and carry the remaining count through every page. Never let a default page size replace the request’s explicit boundary. Record whether the source ended naturally or was cut by the requested limit.

Worker edge

Crash after a side effect

The in-flight step may run twice. Store an idempotency key before the side effect, reconcile provider state on retry, and prefer updating a known artifact over creating another one.

Artifact edge

Provider says “success” but data is wrong

Separate “published” from “verified.” Re-read the provider artifact or parse the file back. Only the verification gate may transition an artifact to deliverable.

User edge

Callback repeats or changes format

Same offer + same format returns the existing artifact receipt. Same offer + another format creates a sibling artifact tied to the same source fingerprint.

Why this matters for Divo

The export should be a small transactional system with a chat interface on top.

The research converges on the same separation: the agent decides intent, while the backend owns state, credentials, bounded reads, retries, artifacts, and proof. Divo already has the right high-level boundary; the next hardening step is to make each boundary visible in persisted state and testable on its own.

Implementation hooks (ranked)

Five changes with the most reliability per line of code.

  1. 01
    Add a durable page checkpoint to the export run.This catches the exact “source re-fetches too much” class of bug and enables resume after a worker crash.
  2. 02
    Introduce a deterministic artifact key and a reconcile-before-create sink.This protects Google Sheets and Drive from duplicate artifacts when a side-effect step is retried.
  3. 03
    Split “published” and “verified” into separate states.It makes provider responses and actual file correctness different, testable facts.
  4. 04
    Return a compact verification receipt to Pi.This preserves the no-large-payload rule while giving the agent enough information for follow-up edits.
  5. 05
    Add fault injection around every external side effect.The happy path already works; crash-window tests are what prove the pipeline is robust.
Probably already considered

Ideas that look simpler, but leave a hole.

  • ↳
    Retry the whole BullMQ job.Fine for pure reads; unsafe once a Sheet/file side effect has happened. Replay should skip committed work.
  • ↳
    Keep the fetched rows in job return values.Works at small volume, but makes queue/DB state and model context fragile. Store large payloads as files or staged pages.
  • ↳
    Treat the provider’s “created” response as completion.Creation proves an object exists, not that the expected rows, columns, types, and values landed.
Risk flags

Do not ship these failure modes as “edge cases.”

  • !
    A retry can create a second Google Sheet or upload a second Drive file.External side effects need a durable idempotency key and reconciliation path.
  • !
    A page checkpoint advances before page data is durably staged.The next retry can silently skip rows.
  • !
    OAuth or service-account credentials cross into Pi/model context.This violates Divo’s authority boundary; Pi should receive only the governed gateway result.
  • !
    A completed export has no reusable resource identity.Continuation then creates a new file or loses the link between chat intent and the artifact.
If I had to reduce the research to one sentence

Divo should treat every export as a durable run with page checkpoints, immutable artifact versions, and a verification receipt—then let chat reveal only the receipt.

This is the smallest architectural shift that captures the strongest ideas from Activepieces, Airbyte, NiFi, Prefect, and the Google Workspace agent references without moving authority into Pi.
